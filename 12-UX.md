# UX/UI Design Specification

## 1. UX principle
The system is an operations tool. Optimize for:
- clarity
- speed
- low cognitive load
- error prevention
- recoverability

## 2. Information architecture

```text
Dashboard
Orders
  ├── All
  ├── Urgent
  ├── Waiting Stock
  └── Exceptions
Inventory
Fulfillment
  ├── Picking
  ├── Packing
  └── Ready to Ship
Shipping
Returns
Reports
Integrations
Settings
```

## 3. Dashboard
Prioritize actionable operational metrics:
- must ship today
- overdue
- at risk
- waiting stock
- ready to ship
- returns awaiting inspection

Avoid making vanity metrics the first screen.

## 4. Warehouse screen
Large controls.
Minimal navigation.
Prominent scan input.
Immediate success/failure feedback.
Keyboard/scanner-friendly.

## 5. Scan interaction

Success:
`✓ SKU MATCH — 2/2`

Mismatch:
`✕ WRONG ITEM — Expected SKU ABC-123`

Do not rely on color alone; include text/icon/state.

## 6. Accessibility
- keyboard navigation
- visible focus
- sufficient contrast
- semantic labels
- error messages tied to fields
- do not communicate status by color alone

## 7. Responsive behavior
Desktop:
- management/reporting

Tablet/mobile:
- warehouse/scan/picking/packing

## 8. Destructive actions
Require explicit confirmation for:
- stock adjustment
- deletion where permitted
- disconnect integration
- cancellation
- bulk mutation

## 9. Empty/error/loading states
Every data-driven page needs:
- loading
- empty
- error
- permission denied
- retry

## 10. UX consistency
Use one design system:
- typography scale
- spacing scale
- buttons
- badges
- tables
- forms
- dialogs
- alerts
- scan feedback
